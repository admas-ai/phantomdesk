# Product direction

Build PhantomDesk, a human-reviewed maintenance-request inbox for a small property-maintenance coordinator. The central promise is that an exported instruction revision is the saved revision a person actually approved. An edit or changed review condition breaks the seal; historical approval remains visible.

Use only synthetic demo data. No automatic assignment, dispatch, deletion, email, or emergency-service decision. Priority suggestions are configurable deterministic rules, not a diagnosis or proof of urgency. Preserve the user's decision and reason in history.

The main category is Costume Contest. Use spooky visual ideas only where they clarify neglected or unreviewed work. Keep literal action names, readable contrast, visible focus, labels and non-color status cues. Respect reduced motion. Test at narrow widths and with keyboard only.

Implement local-first behavior with clear browser-only storage limits. Show a persistent non-alarming message when persistence fails; never say a change was saved when it was not. Keep source portable and dependencies modest. Build only this separate app; do not add paid services, accounts or production integrations. Preserve the existing MIT license and unrelated repositories. General JSON import is deferred in the first slice.

New duplicate relationships must be applied atomically to every affected saved request. A previous dismissal or approval cannot silently cover a new counterpart. Require a new review when a current condition becomes unresolved, and recheck saved eligibility when downloading a CSV.

Authorship is factual: Codex prepared the October 30 brief and November 25 launch inputs; the latest requirements from main are preserved. Record actual Kiro contributions, tests and revisions only after they happen. Do not label this project Kiro-built merely because `.kiro` exists. Treat every unchecked task and `not_run` result as unfinished.
